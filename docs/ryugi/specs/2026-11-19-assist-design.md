# 出牌助手（H.I.F）设计

2026-11-19。仓库 gakumas-bench（初星攻略站），页面路径 `/assist`。

## 为什么做

GKMS 那边有一个独立网站（gkmstest.nyarot.org，GKMSUINetWeb）：玩家填好编成、开始对局，每回合把游戏里实际抽到的手牌点进去，网站用 UINet 告诉你下一步打什么。群里 Ert'Aria 提议把它并进攻略站。用户定：**不做互相跳转，在攻略站里重做一个自己的，直接并进来**。

GKMSUINetWeb 的源码不在 GKMSProject 仓库里，GKMS 也没有开源许可证，所以界面和交互全部自己写；考试推演用我们服务器上已经在跑的 GKMS 引擎子进程，出牌建议用 GKMSUINet 公开的 MIT 模型。

攻略站已经有的东西正好给助手用：中文卡名和效果（汉化插件的翻译）、H.I.F 题库（每题就是一份编成）、配置强度榜、服务器上的 GKMS 引擎和托管对局那一套会话管理。

## 用户定的

| 问题 | 定了什么 |
|---|---|
| 怎么用 | **实战同步为主 + 练习模拟**：主用法是每回合把实际手牌点进来拿建议；同一界面能切成「引擎随机抽牌」完整打一场练手 |
| 模式范围 | **第一版只做 H.I.F**（选拔 1 / 2 / 3、本战上半场 / 下半场），结构留给初、N.I.A、偶像之路 |
| 建议来源 | **只用 UINet**（不做 GNRPA 深算） |
| 设备 | **手机和电脑都要好用**：手机竖屏一列排开、按钮够大，边玩边切过来点；电脑左右分栏 |
| 和 GKMSUINetWeb 的关系 | 不做跳转，自己重做并进来 |

## 目标

1. 填编成：偶像卡、哪场审查、Vo / Da / Vi、体力 / 体力上限、得分加成（可选）、P 道具、饮料、回忆技能、支援卡、卡组。
2. 一键带入编成：从攻略站 H.I.F 题库的某道题；从本机保存的编成；从编成码（我们自己的格式，见下）。
3. 实战同步：每个回合开始时，在「还在牌堆里的牌」里点出这回合实际抽到的几张，引擎局面跟着改；UINet 给出每个合法动作的概率和最终分数预测（10% / 50% / 90% 分位）；玩家点自己实际打的那一步，引擎推进。
4. 练习模拟：不点手牌，引擎按随机牌序抽，玩家照建议或自己选，打到结束看总分。
5. 撤销：任何一步都能退回上一步（点错手牌、点错动作）。
6. 手机和电脑都顺手。

## 不做（第一版）

- 初、N.I.A、偶像之路（UINet 是 H.I.F 训练的；结构留好，接口里带 `mode`）。
- GNRPA / PIMC 搜索建议（用户定只用 UINet）。
- 截图识别局面。
- 培育阶段的决策（买饮料、选卡等）。
- 账号、云端保存：编成只存浏览器本地。

## 绝不做

- 不读种子：实战同步完全按玩家点进来的手牌和画面数值，不推测、不使用游戏的随机数。
- 不搬 GKMSUINetWeb 或 GKMS 的代码（没有许可证）；GKMS 引擎只通过我们现有的引擎子进程调用（和托管对局一样）。
- 不让一个访客压垮服务器：会话数、请求频率都有上限。

## 11-20 用户改定（接手会话 a6262813）

1. **兼容 GKMS「导出 GKMSUINet」的 GR1 码**：玩家从 GKMS 客户端导出后直接粘贴就能导入（第一版就做，不再是可选项）。
2. **考试引擎用 GKMS rev383**（`a9ba6865`，11-16，考试规则 67，主数据含 11-16 新卡）：GKMS 从 Ver3.18.0 / rev384 起保留所有权利，rev383 是最后一个 AGPL-3.0 版本。服务器的 GKMS 一起升到 rev383（裁判也跟着到规则 67）。
3. **UINet 用 GKMSUINet 公开仓库（MIT）的 Ver2.1-Kummertranen**，不用 Ver1.1。

## 约束

- 服务器 ycy：4 核、8 GB，Go 服务器 + 3 个 Python 引擎子进程（`gkbench.worker`，`GKBENCH_WORKERS=3`），同时还跑着托管评测。
- UINet：`gkbench/algos/uinet.py` 已经包了 GKMSUINet 的 `Policy`（ONNX，`decide(obs)` 返回动作、和 `obs["legal"]` 对应的概率、`score_quantiles`）。服务器子进程目前**没装 onnxruntime 和 gkms_uinet**，要补装进 `/opt/gkbench/app/.venv`，模型放 `$GKBENCH_DATA`（或 pip 包自带）。
- 观测：UINet 吃 UIObs v1（`uinet.uiobs.from_session`，裁判 `gkbench/referee.py` 已经在用）。
- 改局面：GKMS 会话支持 `session.edit(fn)`（`gkbench/worlds.py` 已经用它重排牌堆）。
- 网页：React + Vite + TanStack Query，设计规范见仓库 `DESIGN.md` 和 `PRODUCT.md`；部署走 `tools/deploy-web.sh`（干净 worktree 构建、保留旧分片）。
- 中文：卡名、道具名、效果文字走现有 catalog（`api/catalog?lang=zh`），「日 / 中」开关照常生效。

## 怎么做

### 交互流程（玩家看到的）

1. **编成**（`/assist`，默认显示）：上半是「带入」：从题库选一题 / 本机保存的编成 / 粘贴编成码；下半是编辑区：偶像卡（按偶像分组的头像选择）、审查（五个按钮）、数值、P 道具 / 饮料 / 回忆技能 / 支援卡（各一个「添加」弹窗，搜索 + 图标）、卡组（选偶像后专属卡自动加入；「添加技能卡」弹窗；每张卡能改强化 / 定制、删除）。底部：编成名字、保存到本机、复制编成码、开始对局（两个按钮：**实战同步** / **练习模拟**）。
2. **对局**：
   - 顶部状态条：第几回合 / 共几回合、这回合属性（Vo / Da / Vi 颜色）、分数、体力、元気、主要状态（好调、集中、好印象、やる気 等，复用 Replay 页的状态显示）。
   - **实战同步**时，每回合开始先进「点手牌」：列出牌堆里剩下的牌（同名卡合并显示张数），点选这回合抽到的牌（数量和引擎要抽的张数一致才能确认；临时生成的卡用「其他卡」加）。确认后引擎局面换成这手牌。
   - 手牌区：每张卡显示 UINet 概率（百分比 + 条），最高的一张高亮；下面是饮料和「结束回合」按钮，同样带概率。最终分数预测（10% / 50% / 90%）放在建议区顶部。
   - 玩家点一张卡 = 「我打了这张」，引擎推进；回合内继续出牌，直到回合结束，进下一回合的「点手牌」。
   - 数值对不上时（画面上的分数 / 体力 / 元気和引擎不一样），状态条上的数值可以点开改；改了会写进局面。
   - 撤销：退回上一步（局面快照）。
   - 打完：显示最终分数，和「再来一局（同编成）」「回编成」。
   - **练习模拟**：没有「点手牌」，引擎自己抽；其余相同。
3. **手机**：一列排开，顺序是状态条 → 建议（概率最高的动作 + 预测分）→ 手牌 → 饮料 / 结束回合；建议区在滚动时贴在顶部。按钮高度 ≥ 44px。**电脑**：左边局面（状态、手牌、牌堆 / 弃牌），右边建议和操作记录。

### 服务器

沿用托管对局（`server/hosted.go`）的会话管理方式，新开一组接口，不需要登录：

| 接口 | 作用 |
|---|---|
| `POST /api/assist/sessions` `{mode: "hif", loadout, practice: bool}` | 在引擎子进程里开局（练习：随机种子；实战：随机种子，但每回合的手牌由玩家指定）。回 `{session, view}` |
| `POST /api/assist/sessions/{id}/hand` `{cards: [卡的唯一编号…]}` | 实战同步：把这回合的手牌设成这几张（从牌堆移到手牌，原来抽到的放回牌堆）。回新的 `view` |
| `POST /api/assist/sessions/{id}/numbers` `{score?, stamina?, block?}` | 改数值，回 `view` |
| `POST /api/assist/sessions/{id}/step` `{action}` | 打出 / 喝饮料 / 结束回合，回 `view` |
| `POST /api/assist/sessions/{id}/undo` | 退一步，回 `view` |
| `DELETE /api/assist/sessions/{id}` | 结束 |

`view` = 公开局面（UIObs 加上牌堆 / 弃牌的成员、这回合要抽几张、是否在等「点手牌」）+ UINet 建议 `{probs: [与 legal 对应], best, score_quantiles}`。每次局面变化都重算建议（UINet 一次约 10 ms）。

限制：会话闲置 30 分钟回收；全站同时最多 64 个助手会话（和托管对局分开计数）；同一 IP 每秒最多 5 个请求。会话只在内存里，不落盘、不进排行。

### 引擎子进程（`gkbench/worker.py`）

新增 op：`assist_open`、`assist_hand`、`assist_numbers`、`assist_step`、`assist_undo`、`assist_close`（或在现有 open / step 上加参数，由实现者定）。实现要点：

- 局面用 GKMS 会话（和裁判同一套构建 `engine.build(loadout, seed)`），每步之前存快照（`session.clone()`）供撤销，最多留 300 步。
- `assist_hand`：用 `session.edit` 把指定的卡从牌堆移进手牌、把引擎刚抽的放回牌堆顶以外的位置；要校验指定的卡确实在牌堆里、张数对。
- 建议：`UinetAlgo` 的同一个 `Policy`，每个子进程加载一次（ONNX ensemble，约几十 MB 内存）。
- 回合开始时「是否等待点手牌」：实战会话在每次进入新回合的抽牌后置 `awaiting_hand = true`，`assist_hand` 之后清掉；这期间不给建议、不接受 step。

### 编成码

我们自己的格式：`GA1` + base64url(raw deflate(JSON {"v":1, "mode":"hif", "name", "loadout"}))，loadout 用 `gkms.hif_loadout.v1` 的写法（和题库题目同一套字段，见 `gakumas-bench-data/problems/hif/*.gksave.json` 的 `loadout`）。复制、粘贴、本机保存都用它。

### 网页

- 新页面 `web/src/pages/Assist.tsx`（编成 + 对局两个视图，用 URL 参数区分，例如 `/assist?play=<session>`），路由加到 `main.tsx`，顶栏加「出牌助手」。
- 卡、道具、饮料、回忆技能、支援卡的选择器复用现有组件（Cards 页、CardDetail、SupportCard、ItemDetail、DeckView）的展示方式；选择器是新写的弹窗（搜索 + 图标网格）。
- 题库带入：题库页每道 H.I.F 题加「在出牌助手里打开」（站内链接，带题号），助手按题号拉题目 loadout。
- 状态显示复用 Replay 页（`pages/Replay.tsx`）里的状态条、手牌卡面。

## 审稿后补的决定（都是我的决定，用户可改）

审稿子代理按「拿到就开工」读了一遍，问了 7 处；都能按已有讨论和代码定，标在这里：

1. **回合中途的抽牌、保留的牌、回合开始的触发**：实战同步不只在回合开始问，**引擎每次往手牌里加了牌（回合开始抽牌、卡牌效果抽牌、生成卡），都进「核对手牌」**：显示引擎现在的整手牌，玩家把它改成画面上的那一手（保留在手里的牌也在里面，不用区分）。回合开始的触发效果已经按引擎抽到的牌结算过，换牌后可能有小偏差，接受；对不上的数值用「改数值」修。第一件实现任务是验证 `session.edit` 能把指定的牌从牌堆移进手牌、把多出的牌放回牌堆（只用 `worlds.py` 那种重排整个山札不够）；做不到就换成「在抽牌前把指定的牌排到山札顶」的做法。
2. **选牌动作**（`("select", […])`，卡牌效果要你从几张里挑）：UINet 只给出牌 / 饮料 / 结束回合打分，不管选牌。界面在需要选牌时弹出候选让玩家点；建议位置显示「按引擎默认挑法」的结果（GKMS 的缺省选牌策略），不标概率。
3. **五个审查按钮 → loadout**：选拔 1 / 2 / 3 = `produce_id: produce-007`，`round: mid1 / mid2 / final`；本战上半场 / 下半场 = `produce-008`，`mid1 / final`（和 GKMS `uinet_export.ROUNDS` 一致）。`audition_number`、`step_id`、`step_number`、`step_type`、`step_select_number` 等跟审查联动的字段，从题库里同一 (produce_id, round) 的任意一题照抄，编辑器不让玩家改。
4. **引擎子进程重启**：会话直接作废；网页提示「对局断了，编成还在本机，点重开」，一键用同一编成重开。和评测共用现有的 3 个子进程，不单独开。
5. **编成是访客输入，要校验**：开局报错只把简短原因回给访客；卡组最多 60 张、P 道具 / 饮料 / 回忆技能 / 支援卡各有上限（按游戏上限）；`assist_open` 超过 10 秒算失败。
6. **服务器上的 UINet**：装 GKMSUINet 公开仓库（MIT）的 `gkms_uinet` 包和它自带的模型（11-20 改定：Ver2.1-Kummertranen），主数据指向服务器 GKMS 的主数据（`engine.MASTER_DIR`）。
7. **频率限制**：新写一个按秒计的限流（现有的是每小时），IP 取 nginx 传来的 `X-Real-IP`。
